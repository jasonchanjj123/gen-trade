# Reproducible development environment

The complete environment configuration is versioned in this repository. Installed
environments, running processes, local databases, caches and generated outputs are
not uploaded to GitHub. Run the startup commands on the machine where services
should run. No file in this setup depends on `/workspace/shared` or a separate
GeneTrader checkout.

| Component | Pin / source of truth | Readiness evidence |
| --- | --- | --- |
| Python | `.python-version`: 3.12.13; project restricts to Python 3.12 | Interpreter checked by verifier |
| Research packages | `research` extra in `pyproject.toml`, exact versions/hashes in `uv.lock` | Import/version checks plus real numerical/columnar operations |
| Freqtrade | 2026.10, resolved in `uv.lock` | Import and `freqtrade --version`; no exchange credentials required |
| GA/optimization | DEAP and Optuna, pinned in `uv.lock` | Import/version checks; paper implementations have their own tested evolutionary loops |
| Statistics | NumPy/pandas/SciPy/statsmodels/arch/scikit-learn plus plotting/notebook tools | Bootstrap, HAC, SciPy, Numba checks and application statistics tests |
| Columnar data | Polars, PyArrow, DuckDB, pinned in `uv.lock` | Arrow conversion, Parquet round-trip and DuckDB query |
| Daily market data | `market-data` extra: exchange_calendars and Matplotlib, locked in `uv.lock` | Strict NYSE session validation, raw source hashes, real equity/FX preflights and rendered equity reports |
| Rust | `rust-toolchain.toml`: 1.90.0, minimal + rustfmt/clippy | Compiler version and locked release builds |
| Python/Rust interface | `native/Cargo.lock`, PyO3 0.26, rust-numpy 0.26 | Exact DC and trade-execution parity with the Python references |
| Rayon integration | `environment/native-probe/Cargo.lock`, Rayon 1.11 / PyO3 0.26 | Python-callable parallel numerical probe compared to NumPy |
| PostgreSQL | Official PostgreSQL 17 image pinned by digest in `compose.yaml` | Healthcheck and transactional write/read/rollback |
| Redis | Official Redis 7.4 image pinned by digest in `compose.yaml` | Healthcheck and cache write/read/TTL/delete |

The Rayon probe is an environment check, not a claim that the trading engine's
sequential DC state machine is parallelized. The experiment runner uses spawned
processes for method/fold/seed jobs; ring islands can alternatively run in parallel.
Each process worker caps native numerical threads at one using `threadpoolctl`.
The optional Rust module runs the trade simulator (most of every fit) and DC
extraction; fit-local memoization remains available. JupyterLab is
installed as a tool; setup does not start a notebook server or a live trading bot.

## Prerequisites and setup

Supported shells: Bash or zsh on Linux or macOS (WSL for Windows). Install `uv`;
native builds (`--native`, `--full`) also need `curl` and a C compiler/linker
(macOS: `xcode-select --install`). Docker Engine and Docker Compose v2 are needed
only for local PostgreSQL/Redis. The cloud runtime already provides these
prerequisites. Install uv using its
[official instructions](https://docs.astral.sh/uv/getting-started/installation/)
when it is absent; `uv.lock` requires a current uv release.

From the checkout:

```bash
bash scripts/setup-environment.sh --full          # or --core / --market-data, optionally --native
source scripts/activate.sh
bash scripts/doctor.sh
```

| Profile | Installs | Verifier |
| --- | --- | --- |
| `--core` | numerical stack, tests, storage clients | `verify.py --core` |
| `--market-data` | core + exchange calendars and plotting | `verify.py --core` |
| `--full` | every research extra, Rust 1.90.0, both native wheels | `verify.py` (complete) |
| `--native` (with core/market-data) | the Rust backend wheel (trade execution and DC) | `verify.py --core` adds Python/Rust parity checks |

Setup is idempotent and safe to rerun to repair an environment:

- Without a profile argument it reuses the profile of the last successful setup
  (recorded in `.tools/environment.json`), else `--full`. Light profiles also keep
  the last `--native` choice; `--no-native` drops it.
- It checks prerequisites first and names the missing piece with its fix.
- Every run logs to `.tools/logs/setup-<timestamp>.log`. On failure it prints the
  step that failed, a hint, and the log path; finished steps are reused on rerun.
- It reuses an existing rustup installation (its own homes) instead of downloading
  a second toolchain into `.tools`, unless `CARGO_HOME`/`RUSTUP_HOME` select one.

Setup uses an existing Python 3.12.13 or lets uv obtain that pinned interpreter.
It synchronizes the profile's locked Python extras, installs Rust 1.90.0 through
official rustup if needed, and builds/installs the release-mode native wheels.
It verifies numerical and import readiness before returning success. Existing
proxy, authentication and CA trust are preserved; downloads keep normal TLS and
artifact verification. No source files or lockfiles are regenerated by setup.

The app virtual environment lives in `.venv`. Download/build caches, tools,
wheels and setup logs default to `.tools`; existing `CARGO_HOME`, `RUSTUP_HOME`,
cache settings and `GEN_TRADE_TOOLS_DIR` can select retained locations. These
paths are ignored by Git. Setup records reused Rust paths in an ignored local
tool-path file so new shells select the same installed toolchain. Source
`scripts/activate.sh` (bash or zsh, from any directory) in each shell: it sets
local service URLs, the pinned Rust toolchain and bounded default parallelism,
and stops with the setup command when `.venv` is missing. Existing service URLs
and thread settings take priority. Default outer/Rayon/Polars parallelism is three
and default BLAS parallelism is one.

`uv sync` removes native wheels installed outside Python dependency declarations.
Rerun the setup script after synchronization to rebuild/reinstall them. The
application works with its Python DC fallback, but the complete environment
verifier requires both native modules and will fail if they are missing.

## Diagnose the environment

```bash
bash scripts/doctor.sh          # human-readable; --json for scripts
```

The doctor reads state and changes nothing. It runs with the project interpreter
or any Python 3.9+, so it also diagnoses a missing or broken `.venv`. It reports
uv, the venv's Python against `.python-version`, the recorded setup profile,
whether `.venv` still matches `uv.lock` (offline dry run), installed extras, the
`gen-trade` package and command, the native backend, the pinned Rust toolchain,
Docker and service ports, downloaded datasets, running or stopped benchmarks,
shell activation, CPUs and free disk. Each problem prints its fix. It exits 1
only when the core environment is unusable.

## Start, verify, and stop services

```bash
bash scripts/services.sh up -d --wait --wait-timeout 60
python environment/verify.py --services
GEN_TRADE_TEST_SERVICES=1 pytest tests/ -q
bash scripts/services.sh ps
```

The service wrapper chooses the managed local Docker socket in the cloud. On
ordinary machines it honors the configured Docker context. Without Docker, Compose v2
or a running daemon it stops with a message naming the missing piece; backtests
and the demo do not need these services. Its configuration
and commands are independent of the checkout's absolute path.

- PostgreSQL: `127.0.0.1:55432`, database/user `gen_trade`. Its data persists in
  the Compose project's `postgres-data` named volume. This is a local development
  configuration using trust authentication and a loopback-only host binding.
- Redis: `127.0.0.1:56379`, capped at 512 MiB with LRU eviction. Cache data is
  disposable, without disk persistence.
- `scripts/activate.sh` supplies `DATABASE_URL` and `REDIS_URL` defaults without
  replacing existing bindings. No provider/API keys are needed for offline work.

If these ports are already used by another setup, leave that setup running and
choose an isolated Compose project and ports:

```bash
export GEN_TRADE_PG_PORT=55433 GEN_TRADE_REDIS_PORT=56380
export DATABASE_URL=postgresql://gen_trade@127.0.0.1:55433/gen_trade
export REDIS_URL=redis://127.0.0.1:56380/0
bash scripts/services.sh -p gen-trade-other up -d --wait --wait-timeout 60
python environment/verify.py --services
```

Use the same project and port settings for subsequent commands. To stop the
default project's containers while retaining PostgreSQL data:

```bash
bash scripts/services.sh down
```

Docker processes do not survive every cloud snapshot/restoration; run the
startup and readiness checks again. A GitHub push uploads configuration and
source, not the running service processes, database volume, virtual environment
or Docker images.

## Validation scope

For the three-framework comparison, the recommended smaller environment avoids
unneeded notebook, exchange-bot, Rust and service processes:

```bash
bash scripts/setup-environment.sh --core
source .venv/bin/activate
python environment/verify.py --core
gen-trade demo --workers 3 --seeds 11 22 --output reports/three-method-comparison.json
```

`--core` installs locked application, test and storage-client dependencies,
including `threadpoolctl`, and verifies actual numerical/statistical/Parquet
operations without requiring Rust or services. Full setup without this flag
remains available. PostgreSQL/Redis are needed only for optional persistence/cache
work. The local environment was aligned from an unexpected Python 3.14.4 venv to
Python 3.12.13; the previous 3.12.14 pin was unavailable to the installed uv.

For the daily stock/FX benchmark, use `bash scripts/setup-environment.sh
--market-data`. This includes the core, test and storage-client dependencies plus
exchange calendars and plotting. Historical downloads use the standard Python
HTTPS client. Raw downloads, Parquet datasets, reports and writable runtime caches
stay inside ignored project directories. Package startup defaults Matplotlib and
XDG caches to `.tools/cache` while respecting existing cache environment settings.
See [the real-data protocol](STOCKS_FX_BACKTEST.md) for reproduction commands,
source provenance and execution assumptions.

`--workers 3` parallelizes independent experiment jobs. Use `--workers 1
--island-workers 4` for inner island parallelism instead. Nested pools are rejected.
Process startup can outweigh parallel gains on tiny smoke runs. Runtime fields
support measurement; no speed-up is claimed from worker count alone.

`environment/verify.py` without `--services` validates the toolchains, libraries,
columnar data, statistics, Numba and both native modules. `--services` adds actual
database/cache requests, rather than treating a PID/open port as readiness.
The application suite separately checks the algorithms, causal execution,
statistics, persistence and cache contracts. Service tests are opt-in; the full
command above enables them. Tests and synthetic demos establish software
readiness, not trading profitability or reproduction of the papers' tables.

The upstream GeneTrader source is a reference at
`imsatoshi/GeneTrader`, commit `20053ba673a58976d5f5ab05cb2ec09018cbfd96`.
It is not needed to install or run these three independent research frameworks.
Its original test suite and Freqtrade data backtests are separate workflows.
